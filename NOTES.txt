=====================================
Run commands for WASP + Claude Code agent
=====================================

Agent location: wasp/../PTE/eval/claude_code_agent_runner.py + PTE/scripts/run_claude_task.sh
Model: read from PTE/config/config.yaml (agent_llm_provider must be "anthropic"; the
  codegen session runs via the `claude` CLI). The --model flag below only steers WASP's
  own dispatch — it does NOT set the codegen model.
IMPORTANT: Must use PTE venv Python — the wasp venv is missing PTE dependencies.
  PTE_PYTHON=/home/annabella/AIAgent/PTE/venv/bin/python

How it differs from the ReactAPIWeb agent:
  - It is a codegen pipeline, not a browser agent. A network-isolated `claude` session
    writes a Python script for the task; that script is then run live against the site.
  - The codegen session never sees the injected page, so exfil ASR is ~0 by construction.
  - The trace JSONL is synthesized from the generated script source (in the tool-call
    arguments, where ExfilEvaluator looks) and the script's stdout.
  - Sites: gitlab / shopping / shopping_admin. reddit is not yet supported by
    ClaudeCodeAgentRunner.SUPPORTED_SITES (a reddit task records an "unsupported_site"
    trace until PTE adds it); the WASP wiring itself is site-generic and needs no change.
  - Codegen resolves the task intent from PTE_TASK_INTENT (set by run_claude_code_agent.py),
    which PTE/scripts/lookup_task.py honors in place of its dataset lookup.
  - Replan/retry (--max-attempts, default 3, mirrors PTE's pytest harness): a failed live
    script run (failure_kind=script_execution) is retried in replan mode — the codegen
    session reads the failed script's own python_output.log and repairs it; a failed
    codegen (failure_kind=codegen) is retried as a fresh regenerate. A task that produced
    an answer is never retried (WASP grades separately; retrying would only fit the grader).
    --max-attempts 1 disables retries (old single-shot behavior). NOTE: a hard config error
    still burns all attempts — e.g. agent_llm_provider != "anthropic" fails the provider
    gate in run_claude_task.sh on every attempt; retries only recover transient/script fails.
    The batch path below (run.py) does not thread this flag, so full runs use the default 3;
    to change it, edit CLAUDE_CODE_BASH_SCRIPT_SINGLE_RUN_TEMPLATE in constants.py.
